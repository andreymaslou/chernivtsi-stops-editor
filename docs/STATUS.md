## 1. Что где крутится

| Что | Где | Как поднять |
|---|---|---|
| Эмулятор + API (**стенд в прод-режиме**, с 2026-09-23) | **`https://169.58.82.105.nip.io/`** — nginx (TLS + Basic Auth), прямое `:8000` закрыто биндом (см. §5.1) | `git pull` → `docker compose up -d --build` |
| HTTPS на своём домене (когда появится A-запись на наш VPS) | `https://<домен>/` тем же nginx-конфигом: подмена домена в конфиге + перевыпуск сертификата | `deploy/README_HTTPS.md` (§0.1 — грабли, §2 — команды) |
| UI | `/ui/editor.html` (редактор маршрутов + панель эмулятора, объединённая), `/ui/emulator.html` (эмулятор отдельно), `/ui/admin.html` (сленг + жалобы), `/docs` (Swagger) | — |
| Локальный dev | `0.0.0.0:8000` | `cd chernivtsi-stops-editor && python main.py` |
| Тесты | локально | `python -m pytest -q` (сейчас 83 passed) |

**Текущий режим — стенд с настоящим HTTPS (с 2026-09-23), а не песочница по IP.**
В `docker-compose.yml` стоит `"127.0.0.1:8000:8000"`: наружу смотрит только nginx
(`:80` → 301 → HTTPS, `:443` под Basic Auth). Зачем это сделали: Web Speech API
(голосовой ввод AI-помощника) и Geolocation живут **только в secure context** —
по `http://<IP>` браузер блокирует микрофон целиком, без системного запроса
(`permissions` сразу `denied`, `mediaDevices` отсутствует), поэтому голос там не
«подключался» принципиально. Риск №1 остался прежним — **деньги**: `/api/route`
вызывает LLM и тратит ключ OpenRouter. Держите лимит расхода в кабинете
OpenRouter либо гасите контейнер, когда не тестируете (`docker compose stop`).
Подробности перехода и найденные грабли — §5.1.

### Как заходить на стенд (и как делиться ссылкой)

1. Открыть **`https://169.58.82.105.nip.io/`** (nginx сам редиректит на
   `/ui/editor.html`). Домена нет — используется публичный DNS-сервис **nip.io**:
   любое имя вида `<IP>.nip.io` резолвится в этот IP, а Let's Encrypt на такое
   имя сертификат выдаёт. Заходить нужно **по имени**, не по голому IP: сертификат
   выписан на `169.58.82.105.nip.io`, поэтому `https://169.58.82.105/` даст
   предупреждение браузера.
2. Браузер спросит **Basic Auth** (это уже защита nginx, а не «шторка» страницы):
   логин `admin`, пароль — на сервере в `/root/https_basic_auth_credentials.txt`
   (хеши — `/etc/nginx/.htpasswd_transgps`). **Пароль в репозиторий не коммитим**:
   репозиторий публичный, а адрес стенда и так виден в Certificate Transparency.
   Сменить пароль: `sudo htpasswd /etc/nginx/.htpasswd_transgps admin`.
3. Прежняя In-page «шторка» редактора (пароль `15201520`) убрана из кода
   (`86abda3`) — отдельно вводить её больше не нужно.
4. `http://169.58.82.105:8000/` **больше не работает** (порт забинден на петлю) —
   это осознанно, иначе Basic Auth обходится прямым заходом.

Поделиться стендом = отдать ссылку `https://169.58.82.105.nip.io/` + логин/пароль
Basic Auth. ⚠️ В мобильное приложение (RN) эти же креды придётся положить
в конфиг — без них API отдаёт `401`.

**Разделяй «5» автобус и «5» троллейбус** (правка подбирается к коммиту):
номера маршрутов у автобусов и троллейбусов независимы — «5» есть и там, и
там, и это два разных маршрута (автобус: Держуніверситет → вул. Ентузіастів;
тролейбус: Калинівський ринок → вул. Південно-Кільцева). Роутер же
идентифицировал машину в парке **только по нормализованной подписи маршрута**
(`_live_by_route` с ключом `"5"`), поэтому оба маршрута склеивались в одну
кучу: «перший потрібний ТС» автобусного 5 мог быть троллейбусом 5, на карту
плана автобуса рисовались троллейбусы, а цвет линии прилетал от чужого типа.
Данные были ни при чём (`graph.json`, `routes_schedule.json`, scraped-файлы
корректно разнесены по `bus:`/`trolley:`) — ломалось в коде. Починено:
индекс парка и все привязки к маршруту (`set_live`, `_approaching_vehicles`,
`_vehicles_for_routes`, `_transit_leg`) идут по паре `(тип ТС, подпись)`;
`vehicle_type` вошёл в `_FLEET_KEY_FIELDS` (смена типа машины обязана
сбрасывать кэш геометрии); на фронте ключ маркера и цель подсветки —
`тип|метка|борт`. Тесты: `test_same_number_different_vehicle_type_stays_separate`
и `test_foreign_vehicle_type_is_not_first_bus`. Замер на тех же данных:
`bus:5:A` — было 12 машин типов `['bus','trolley']`, стало 4 типа `['bus']`;
`trolley:5:A` — было 12 смешанных, стало 8 типа `['trolley']`. pytest 16 → 18.

**Голосовий шар і розбір фрази LLM** (`c96b39a`, `31eaff5`, `14f649c`):
у системний промпт підставляється список реальних місць (`stops.json` + сленг;

## 4. Грабли (чтобы не наступить снова)

1. `set_live()` **внутри** обработчика запроса (`main.py`) — поэтому кэш
   геометрии сбрасывается не по факту вызова, а по смене подписи позиций.
2. `bench3.py` устарел: счётчики не подключены, `set_live` без `snapshot_at`
   (другой режим, +800 `_wait_info`). Используйте `tools/perf`.
3. Поиск «фраза → остановки» идёт через LLM: без `--now` локальный сервер и VPS
   дают разные планы (разные часы и разный парк симулятора), а кириллица в
   `.cmd`-файле вообще ломается в OEM-кодировке — передавайте `--text-file`.
4. `path` ноги — цепочка остановок; для трассировки по улицам нужны OSM way-линии.
5. UI-проверку (`tools/ui/check_emulator.js`) запускать в headless Chromium, а не
   «глазами по скриншоту»: она ловит и курс, и движение (сравнивает позиции
   маркеров в пикселях), и 404/ошибки консоли. Из `run_commands` вывод длинного
   node-процесса обрезается — гоняйте через `.cmd` в скрытом окне
   (`Start-Process -WindowStyle Hidden`), результат читайте из файла.
6. Поворот стрелки ТС — внутри SVG (`<g class="veh-arrow-group" transform="rotate(a 18 18)">`),
   поэтому круг с номером маршрута и попап остаются прямыми. Не вешайте CSS-`rotate` на
   весь маркер: подписи поедут. Правила трёх станів — в `web/emulator.html`
   (`.veh-wrap.planned/.stopped/.target`), вся вёрстка — по-прежнему в `vehicleIcon()`.
7. Симулятор отдаёт `speed_kmh` = средняя скорость маршрута (~20 км/ч), поэтому
   состояние `stopped` (< 3) на нём не воспроизводится — оно только у реального GPS.
   UI-проверка поэтому тестирует CSS-правила `stopped` на одноразовых элементах, а не
   на живых маркерах: иначе ветку нельзя проверить машинно вообще. `opacity`/`filter`
   не наследуются — читайте их у `.veh-wrap`, а не у вложенного `svg`.
8. `L.DomEvent.disableClickPropagation()` (легенда) **не останавливает DOM-бабблинг
   клика**: Leaflet 1.9 ставит на элемент флаг `_leaflet_disable_click`, который
   игнорирует сам движок карты. Слушать `.leaflet-container` в UI-тесте бессмысленно —
   клик туда долетит. Проверяйте поведение: `map.on('click')` и `map.getCenter()` до/после
   драга (обязательно с контрольным измерением мимо легенды, иначе тест ничего не
   доказывает). Карта из `page.evaluate()`: на автономной `/ui/emulator.html` —
   по имени `map` (эмулятор публикует `window.map`, т.к. сам он в IIFE), на
   объединённой `/ui/editor.html` — `window.Emulator.map` (или
   `window.TRANSPORT_MAP`, публикует `web/app.js`). Голого `const map` верхнего
   уровня больше нет: `web/emulator.js` завёрнут в IIFE (см. п. 20).
9. Легенда живёт в `web/emulator.html` (`.map-legend`, `.legend-row`, `.legend-icon`),
   разметка — в `LEGEND_ROWS` + `legendIconStyle()` в `web/emulator.js`. Меняете
   подписи/цвета — правьте `LEGEND_ROWS`, а не HTML, иначе UI-тест разойдётся с кодом.
10. Порог «разгрузки» — `DOT_ZOOM_BELOW` в `web/emulator.js`, а карта открывается
    на `zoom 13`: порог `< 14` показывал бы точки сразу при загрузке, поэтому
    режим точек — это `zoom < 13`. Меняете порог — правьте и комментарий у
    `body.zoom-out` в `web/emulator.html`; UI-тест проверяет оба состояния
    (`map.setZoom(12)` и `map.setZoom(14)`), а не классруками.
11. Сжатие маркера — `transform` **на `.veh-wrap` (36 px)**, не на `.veh-marker`:
    Leaflet сам пишет инлайновый `transform: translate3d(...)` на элемент маркера
    (его же читает проверка «машины двигаются»), поэтому CSS-transform там был бы
    перекрыт. А `popupAnchor` и якорь считаются от обёртки — потому точка и попап
    остаются на месте (тест меряет расхождение: 0 px на обоих зумах).
12. **Симулятор «затискає» ніч до середини дня** (`sim_layer._virtual_minutes`):
    поза вікном роботи маршрутів будь-який `now` дає ОДНУ й ту саму позицію
    парку. Через це UI-перевірка «машины двигаются» падала після опівночі
    (`0 из 119`): рух неможливо довести, бо модель часу не рухає парк. Тепер
    `tools/ui/check_emulator.js` сам ставить час моделі (`--model-time`, типово
    `2026-09-17T12:00`) — результат не залежить від годинника машини.
13. **Курс ТС не можна порівнювати з хордою довгого сегмента**: сегменти бувають
    по кілометру, і на кривій хорда розходиться з напрямком дороги до 90° —
    зустрічні машини проходили фільтр. Тому `_heading_matches_route()` бере
    азимут «від машини до наступної ЗУПИНКИ ланцюжка» (через `route_stop_indices`,
    а азимут сегмента — лише коли машина стоїть рівно на зупинці).
14. **`leg.full_geom` — це зупинки напрямку, а не геометрія доріг** (те саме, що
    `path`): хвіст і активна лінія — прямі між зупинками, на довгих перегонах
    виглядають кутово. Інваріант «`path` — неперервний сріз `full_geom`» тримає
    pytest (`test_leg_full_geom_covers_active_path`): якщо він зламається, хвіст
    на карті не зійдеться з лінією (клієнт тоді просто не малює хвіст).
15. **Headless Chromium віддає `prefers-reduced-motion: reduce`** — усі пульсації
    (`pulse-target`, `pulse-stopped`, `pulse-step`) у UI-перевірці вимкнені, поки
    вона явно не попросить `no-preference` через `page.emulateMediaFeatures`.
    Якщо додаєте нову анімацію з `@media (prefers-reduced-motion)`, перевіряйте її
    тим самим способом (і фіксуйте вимкнення окремим ассертом).
16. **Додане поле в план ламає `compare_snapshots.py`** (він порівнює плани
    побайтово): усі 6 еталонних пар стають `IDENTICAL: False`. Це не регресія —
    запускайте з `--ignore-keys <поле>` (список ігнорованих полів і шлях першої
    розбіжності друкуються в звіті), інакше ускорення буде нечем прийняти.
17. **Номера маршрутів у автобусів і тролейбусів НЕ перетинаються.** «5» —
    це одразу два маршрути (автобус і тролейбус) з різними ланцюжками, і так
    само 1/3/4/6/8. Тому будь-яка прив'язка «парк ↔ маршрут» ідентифікує
    маршрут **парою (тип ТС, підпис)**, а не лише підписою: індекс
    `_live_by_route` у `set_live()`, вибірка кандидатів у `_approaching_vehicles()`,
    список ТС плану у `_vehicles_for_routes()`, колір ноги у `_transit_leg()`.
    За голої підписи вони злипались би в один ключ `"5"` — і «перший потрібний
    ТС» автобусного 5 ставав тролейбусом 5. Те саме на фронті: ключ маркера і
    ціль підсвічування — `тип|метка|борт` (`vehicleKey`/`boardKey` у
    `web/emulator.js`), бо бортові номери теж можуть збігатися між типами.
    Додаєте нове місце зіставлення парку з маршрутом — одразу пишіть про тип
    у коментарі, а краще одразу покривайте його тестом
    (`test_same_number_different_vehicle_type_stays_separate`).
18. **Шеврони напрямку: в `leg.path` трапляються ділянки «туди-назад».** Маршрут
    може проходити одну й ту саму дорогу в обидва боки (виїзд/петля), тоді у
    сегментів `A→B` і `B→A` **однаковий центр**, але азимути розходяться на 180°.
    Перевірка `check_emulator.js` (`expectedBearings`) збирає **усіх** кандидатів
    із таким центром і засчитовує збіг із будь-яким — чий азимут збігається, той
    сегмент і намальовано. Не поверніть її до «першого збігу»: на плані
    «Соборка → Гравітон» (bus 9A) це давало 2 ложних провали (want 155.7 vs
    got 335.7 — різниця рівно 180°). Якщо хочете перевіряти ще й
    візуальний `transform: rotate()` шеврона — беріть `data-bearing`, він
    незмінно фіксує азимут сегмента (`midChevron` у `web/emulator.js`).
    (Кількість шевронів на плані тепер ~7, а не ~105: вони ставляться не на
    кожному сегменті, а кожні `ARROW_MIN_SEGMENT_M` — п. 19.)
19. **Індекс у просторі ЗУПИНОК vs простір розширеної геометрії** — *історія*:
    три візуальні регресії після підключення OSRM. **OSRM вимкнено** (геометрія
    сегмента — пряма між остановками, `route_coords` == зупинки), тому регресії
    неможливі за побудовою, але урок лишається чинним: якщо колись знову
    розширите `route_coords`, індекси зупинок дає тільки `route_stop_indices`
    (еталон — `tests/test_router_plan.py::test_live_snap_stays_in_stop_index_space`,
    тепер він перевіряє саме інваріант просторів, а не факт розширення).
    Нижче — що це було і як лікувалося:

    * **«перший потрібний ТС» зник** (`live_bus` став `None` усюди, золотий бейдж
      цілі нікому було підсвічувати). Цикл прив'язки машини у
      `_approaching_vehicles()` ітерував по ВСІХ точках `route_coords`, тому
      `best_idx` був індексом OSRM-точки (~200), а `board_pos`, `route_prefix`,
      `route_bearings`, `route_segment_m` живуть у просторі зупинок (~14).
      Порівняння `best_idx >= board_pos` відкидало кожну машину як «ту, що вже
      проїхала нашу зупинку». Тепер цикл іде по `route_stop_indices`, і `best_idx`
      знову індекс зупинки; наступний вузол у `_heading_matches_route()` теж
      береться через `stop_indices`, а не як `coords[index+1]`.
    * **крапки зупинок на кожній вершині геометрії**: `renderPlan` малював крапку
      на кожній точці `leg.path` (їх ~250). Тепер бекенд віддає координати
      проміжних зупинок окремим масивом `leg.stops` (збирає `_transit_leg()`), і
      крапки малюються тільки з нього (очікування в `tools/ui/check_emulator.js`
      теж перераховане на `leg.stops`).
    * **шеврони злиплися в купу**: перевірка `> 30 м` малювала шеврон на кожному
      OSRM-сегменті (майже всі вони довші за 30 м). Тепер довжина накопичується по
      точках лінії, і шеврон ставиться кожні `ARROW_MIN_SEGMENT_M` зі скиданням
      лічильника.

    Якщо додаєте щось нове поверх `route_coords` — перевірте, чи не змішали
    простори: зупинкові індекси дає тільки `route_stop_indices` (еталон —
    `tests/test_router_plan.py::test_live_snap_stays_in_stop_index_space`,
    який і моделює цю регресію: машина на зупинці ~6 прив'язується до ~165-ї
    точки геометрії, а посадка — на зупинці 8).

      (текст + кнопка-пилюля) и висит на `bottom: 52px` над кнопкой; легенда
      поднята над ней на `margin-bottom: 116px` и стала компактнее
      (mobile-блок в `emulator-panel.css`). Наложения прямоугольников проверяет
      `tools/ui/check_emulator.js` п.8 на 390px.
    * **легенда — это и есть `.leaflet-control`**: Leaflet вешает класс
      `leaflet-control` на тот самый `div`, который возвращает `onAdd`, поэтому
      позицию контрола задаёт `leaflet.css` —
      `.leaflet-bottom .leaflet-control { margin-bottom: 10px }`. Селектор
      `.map-legend` (0,1,0) его НЕ перебивает: нужно `.leaflet-bottom .map-legend`
      (0,2,0), иначе подъём молча не применяется (ловится пробником по
      `getComputedStyle(...).marginBottom`).

      `#emu-panel` базовий `z-index: 1100`, а `.sheet-scrim` — `1240`. Шторка
      відкривається й виглядає нормально, але всі тапи (textarea, чипы, кнопки)
      ловить скрим — і навіть закриває шторку. Симптом користувача: «панель
      виїжджає, але неактивна». Верхня шторка працювала тільки тому, що в
      `.drawer` стоїть `1245`. Порядок шарів: карта `0` → скрим `1240` →
      редактор `1245` / емулятор `1250` → кнопки-пилюли `1300`. Ловиться
      хит-тестом (`document.elementFromPoint` у центрі шторки мусить дати
      елемент усередині неї) — тепер це окремі пункти в
      `tools/ui/check_emulator.js` п.6.1, плюс «жива» перевірка вводу в
      `#ask-text` усередині шторки. **Одного `z-index` шторці замало**: вона
      лежить усередині `.map-container`, а той на мобільних був
      `position: fixed`, і `fixed` сам створює stacking context — тоді
      `z-index: 1250` рахується всередині карти (рівень `0`) і скрим усе одно
      зверху. Тому карта тепер `position: absolute` (без `z-index`) — контекст
      не створюється, і шторка справді перемагає затемнення. Перевіряти треба
      хит-тестом (`elementFromPoint`), геометрія цей баг не ловить.

      уезжают под «бровь» и полоску-индикатор. Первая строка в правиле — фолбэк
      для браузеров без `env()`.

26. **Метка маршрута в расписании — это ключ, и она обязана совпадать с графом.**
    В `routes_schedule.json` метки двух маршрутов были написаны **кириллицей**
    («8А», «15К»), а граф отдаёт латиницу (`bus:8A:A`, `bus:15K:A`).
    `_schedule_for()` ключ не находил и возвращал `None`, а дальше — молча:
    * `price_grn` ноги становилась **0** (итог «Соборка → Гравітон» был 36 вместо
      правильных 56 — цена врёт в меньшую сторону, и это «дешёвый» маршрут);
    * ожидание падало на `DEFAULT_WAIT_MINUTES` вместо интервала маршрута;
    * ночное «не ходить» не срабатывало: 8A/15K считались ходящими круглосуточно.
    Замер: **37 из 234 планов (15.8 %)** задевали 15K (30) или 8A (7), и каждый раз
    цена ноги была нулевой. После фикса: 0 планов без расписания, 0 нулевых цен.
    Исправлено в двух местах: метки в файле приведены к латинице, а
    `_schedule_for()` ищет по индексу `_schedule_by_label` (нормализация через
    `normalize_label`, куда добавлена кириллическая `к`).
    Инварианты — `tests/test_schedule_labels.py` (каждый маршрут графа обязан
    найти и расписание, и тариф; отдельный тест ловит возврат кириллицы в файл).
    ⚠️ **Базлайны `compare_snapshots.py` переснимать НЕ нужно:** прогон «до
    (212fa3f~1, кириллица)/после» на всех 6 эталонных планах `latency_plan.py`
    даёт `identical=True` — ни пара 107↔166, ни 181↔166 маршрутов 8A/15K не
    используют. А вот **парк симулятора изменился**, потому что 8A/15K больше не
    берут first/last/interval по умолчанию: ночь 124 → **120** ТС, день 128 →
    **125** (`tests/conftest.py: EXPECTED_FLEET_SIZE = 119` — историческая цифра,
    нигде не проверяется). Поэтому цифры по случайным парам, где 8A/15K
    встречаются (15.8 %), сравниваются с неверным «до» — переснять их стоит, а
    видимый пользователю эффект правильный: «Соборка → Гравітон» теперь

    нормализации — поэтому в файле держим латиницу.

## 8. Идеи (Future UX Features)
Сборник идей для будущих интеграций (особенно после полноценного внедрения ИИ-моделей вроде Jev):

*   **Интерактивные промежуточные остановки (Smart Layovers):** При тапе на любую промежуточную остановку отрисованного маршрута показывать её название и расчетное время прибытия именно этого автобуса (ETA).
*   **Перехват маршрута (Смена точки Б):** При тапе на остановку в середине предложенного маршрута предлагать кнопку *"Поїхати сюди"*, которая "обрезает" маршрут и перестраивает его до этой новой точки.
*   **Перестроение маршрута (Смена точки А):** Тапнув на любую промежуточную остановку, можно выбрать *"Як доїхати звідси?"*, что мгновенно делает эту остановку новой стартовой точкой для следующих поисков.
