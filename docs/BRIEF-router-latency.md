# BRIEF: Возврат Latency (Сплит геометрии и времени) + Гигиена (chernivtsi-stops-editor)

**Цель 1:** Вернуть latency функции `plan()` к заветным <100 мс, не жертвуя корректностью.
**Цель 2:** Навести порядок в репозитории (гигиена) перед выходом в прод (HTTPS/Auth).

**Анализ проблемы (почему выросла latency):**
Из-за включения `board_time` в ключ кэша `_wait_info`, мы стали гораздо чаще промахиваться мимо кэша. Это приводит к повторному вызову `_nearest_live_vehicle`. 
Внутри `_nearest_live_vehicle` выполняется дорогой геометрический расчет (haversine) для привязки координат живых автобусов к узлам маршрута. 
Но **позиции автобусов фиксированы** на время выполнения одного запроса `plan()`! Геометрия не зависит от того, во сколько пассажир придет на остановку.

---

## 1. Шаг 1: Разделение пространственной и временной логики (Возврат Latency)

*   **Файл:Функция:** `router_layer.py : _nearest_live_vehicle()`
*   **Суть:** 
    1. Расчет базовых метрик (какой автобус где едет, сколько ему ехать до `board_node` без учета времени пассажира) зависит только от `route_key` и `board_node`.
    2. Нужно создать отдельный пространственный кэш на уровне экземпляра (или в рамках вызова `plan()`): `self._spatial_cache = {}`. Ключ: `(route_key, board_node)`.
    3. Значение кэша: отсортированный список всех машин на этом маршруте, которые едут в сторону `board_node`, с их базовым `eta_min` (через сколько минут они физически доедут до остановки от своей текущей позиции).
    4. Функция `_nearest_live_vehicle` должна сначала проверить `_spatial_cache`. Если его нет — посчитать геометрию (haversine) и положить в кэш.
    5. После получения списка машин из `_spatial_cache` (это уже `O(1)`), функция просто применяет временной фильтр: отсекает машины, у которых `eta_min < passenger_arrival_min`, и возвращает первую подходящую.
*   **Ожидаемый эффект:** Вызовы `_haversine_m` упадут с ~66 000 обратно к ~9 000. Latency `plan()` упадет с 200-310 мс обратно к ~90-100 мс. Корректность ответа (тесты) не изменится.

## 2. Шаг 2: Гигиена репозитория (Подготовка к проду)

*   **Файл:** `.gitignore`, удаление файлов из git.
*   **Суть:**
    1. Создать `.gitignore` (добавить `__pycache__/`, `*.log`, `_*.txt`, `_*.py`, `_*.png`, `.env`, `node_modules/`, виртуальные окружения).
    2. Убрать из индекса Git мусорные файлы: огромный дубль `streets.json` (если он есть в `data/`), тяжелые скриншоты (`_editor_shot.png`).
    3. Добавить `.env.example`.
    4. Зафиксировать версии зависимостей (`requirements.txt` / `package-lock.json`), если это еще не сделано окончательно.

## 3. Процедура замера и приемки

1. Запускаем набор тестов (`pytest`) — все 5 тестов обязаны пройти без изменений. Это гарантирует, что пространственный кэш не сломал логику отсева уехавших машин.
2. Запускаем `bench3.py` — убеждаемся, что latency `plan()` упала до ~100 мс.
3. Проверяем чистоту статуса репозитория (`git status`) — не должно быть видно мусорных логов и временных скриптов (файлы начинающиеся с `_`).

## 4. Что НЕ трогать

*   Не ломать логику `effective_at` из прошлого фикса.
*   Не менять сигнатуру ответов API.
